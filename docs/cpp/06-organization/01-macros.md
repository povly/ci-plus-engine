# Макросы и препроцессор

Препроцессор — «тупой текстовый редактор», который проходит по коду **до**
компилятора: подставляет, вырезает, вставляет файлы. Никакой проверки типов.

## Вставка файлов

```cpp
#include "engine/Log.h"     // вставить содержимое файла сюда
#pragma once                // «включать этот файл один раз»
```

Без `#pragma once` (или классических include guards) двойное включение = две
копии всех объявлений = ошибка компиляции.

## Макрос-константа и макрос-функция

```cpp
#define BIT(x) (1 << x)
```

Использование `BIT(3)` заменяется на текст `(1 << 3)` ещё до компиляции.
Скобки обязательны: без них `BIT(0) | BIT(1)` превратилось бы в `1 << 0 | 1 << 1`
— а вдруг аргументом будет выражение?

## Макрос, генерирующий методы

```cpp
// Event.h
#define EVENT_CLASS_TYPE(type) \
  static EventType GetStaticType() { return EventType::type; } \
  virtual EventType GetEventType() const override { return GetStaticType(); } \
  virtual const char* GetName() const override { return #type;
```

- `\` в конце строки — «продолжай макрос на следующей».
- `#type` — «сделай из аргумента строку»: `EVENT_CLASS_TYPE(WindowResize)` →
  `return "WindowResize";`.

Без макроса эти три метода копировали бы руками в каждый из ~15 классов
событий. Макрос тут — осознанный компромисс.

## Источник граблей, встреченный прямо в этом проекте

Макрос в `Log.h` заканчивался `\`-переносом, а файл не заканчивался переводом
строки — и компилятор предупреждал «backslash-newline at end of file».
Фикс — просто добавить перевод строки в конце файла. **Всегда заканчивай
файлы пустой строкой.**

## Условная компиляция

```cpp
// Core.h
#if defined(_WIN32)
  #define POVLY_API __declspec(dllexport)   // Windows
#else
  #define POVLY_API __attribute__((visibility("default")))   // Linux/clang/gcc
#endif
```

`POVLY_API` помечает классы, которые библиотека «экспортирует» наружу — без
этого Windows-библиотека их не увидит. На один и тот же смысл — разные
механизмы платформ, и `#if` выбирает нужный **до компиляции**.

## Макросы vs constexpr/inline (современно)

- `#define PI 3.14` → лучше `constexpr double PI = 3.14;` (типизировано, видно отладчику)
- макрос-функция → лучше `inline`-функция или шаблон (проверяется компилятором)

Макросы остаются нужны для того, что функциями быть не может: условная
компиляция, `#type`-строки, генерация повторяющихся кусков класса.
