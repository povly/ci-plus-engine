# Псевдонимы типов: `using` (и старый `typedef`)

```cpp
// src/engine/KeyCodes.h
#include <cstdint>

namespace Povly {
using KeyCode = uint16_t;   // «KeyCode — это другое имя uint16_t»
}
```

Теперь весь движок пишет `Povly::KeyCode` — читается осмысленно, и если
завтра понадобится 32-битный код клавиши, меняется **одна строка**.

## Фиксированная ширина целых

`uint16_t` из `<cstdint>` — «беззнаковое целое ровно 16 бит». В отличие от
`int`/`short`, размер которого зависит от платформы. Для бинарных интерфейсов
(коды клавиш GLFW, сетевые протоколы, файлы) — всегда фиксированные типы:
`uint8_t`, `int32_t`, `uint64_t`...

## typedef — как писали раньше

```cpp
typedef unsigned short KeyCode;   // C-стиль, до C++11
using KeyCode = uint16_t;         // C++11 и далее
```

Оба работают, но `using`:

- читается слева направо: «новое имя = что»;
- работает с шаблонами: `template<class T> using Vec = std::vector<T>;`
  (с typedef так нельзя);
- единообразно с остальным современным кодом.

Ещё одна пара «было/стало» того же рода: `NULL` (макрос, по сути `0`) →
`nullptr` (настоящий указатель-на-ничего, типобезопасен).

```cpp
int* p = nullptr;   // правильно
int* p = NULL;      // работало, но NULL мог неожиданно вести себя как int 0
```
