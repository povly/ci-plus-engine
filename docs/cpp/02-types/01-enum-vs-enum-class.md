# `enum` vs `enum class` vs `enum : T`

В коде движка есть **все три вида** перечислений — и каждый выбран осознанно.

## 1. `enum class` — строгий идентификатор

```cpp
// Event.h
enum class EventType {
  None = 0, WindowClose, WindowResize, WindowFocus, ...
  KeyPressed, KeyReleased, KeyTyped, ...
};
```

- Значение только через имя типа: `EventType::WindowResize`.
- **Не** превращается в число неявно: `if (type == 3)` — ошибка компиляции.
- Имена не «вываливаются» в окружающее пространство.

Это тип-идентификатор: сравнивается только сам с собой. Идеально для
«какой тип у события?» — нельзя случайно перепутать с числом или с другим enum.

## 2. Обычный `enum` — битовая маска

```cpp
// Event.h
enum EventCategory {
  None = 0,
  EventCategoryApplication = BIT(0),  // 1
  EventCategoryInput       = BIT(1),  // 2
  EventCategoryKeyboard    = BIT(2),  // 4
  ...
};
```

- Значения доступны без префикса: просто `EventCategoryApplication`.
- **Неявно приводится к int** — и здесь это плюс: категории склеиваются через
  `|` и проверяются через `&` без всяких кастов (см. `02-bitmasks.md`).

## 3. `enum : KeyCode` — обычный enum с заданным типом хранения

```cpp
// KeyCodes.h
using KeyCode = uint16_t;

namespace Key {
enum : KeyCode {   // фиксированный размер, но БЕЗ строгой типизации
  Space = 32,
  A = 65,
  ...
};
}
```

- `: KeyCode` после слова enum задаёт **тип под капотом** (здесь 16-битный).
- При этом значения по-прежнему нестрогие и совместимы с числами — важно,
  потому что эти коды приходят из GLFW (C-библиотеки), которая работает
  с обычными int.

## Таблица различий

| | `enum class` | `enum` | `enum : T` |
|---|---|---|---|
| Доступ к значению | `Type::Value` | `Value` | `Value` |
| Неявно в int | нет | да | да |
| Имена наружу | нет | да | да |
| Свой тип хранения | по умолчанию int | int (могло отличаться до C++11... строго fixed только с fixed underlying) | да |
| Для чего тут | идентификатор типа события | маска категорий | совместимость с GLFW |

Упрощённо: **enum class — «имена», обычный enum — «числа с именами»**.

## Деталь, которая всё объясняет

Оба enum'а в Event.h содержат `None = 0` — и это **не конфликтует** только
потому, что `EventType::None` спрятан внутри своего типа. А `None` от
EventCategory утёк в пространство `Povly`. Заведи рядом ещё один обычный enum
с `None` — уже ошибка компиляции. Это наглядная цена нестрогости.

## Правило на будущее

По умолчанию пиши `enum class`. Отступай к обычному `enum` только когда нужны
битовые операции или совместимость с C-кодом (как тут) — и понимай, чем платишь.
